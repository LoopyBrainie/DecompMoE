# Change α design — 数值字面量 provenance 修复

## A1 — 修法不是「换一个魔法数」

把 `5.01e-52` 换成 `1.4635872379108090131680874e-17` **本身仍然是换魔法数**：新数字同样没有 provenance，同样无法被后来者判断真假。区别只在于新数字在量纲上说得通。

所以每处替换必须同时给出三件事：

1. **真值**，附求值方式（mpmath dps=60 + 4 参 `betainc(a, b, 0, x, regularized=True)`；3 参形式返回补值 `1−I_x`，**不得使用**——这是本仓第一次 oracle 栽的坑）。
2. **这个量由什么决定**。不是「float64 精度下界」，而是 `sphere._cap_radius` 的二分停止判据 `|G − 1/N_e| < 1e-13`。这一点必须写出来，因为它是 `1e-52` 荒谬性的**机制性解释**：oracle 在自己的 bracket 内把残差压到了 `~1e-52`，然后把这个 bracket 残差当成了 canonical 根处的残差。
3. **可复算入口**：本 change 的 `evidence/_alpha_forensics.py`。

## A2 — 量纲自洽性作为可复用的判别手段

`1e-52` 之所以能被识破，靠的不是重算，而是一个更便宜的自洽性检查：

> 若残差为 `r`，则被积函数值必须与目标值吻合到 `-log10(r)` 位十进制。
> `r = 5.01e-52` ⇒ 需要 50.1 位十进制。
> 单次 float64 运算的舍入下界约 `1e-16`（53 位尾数）。
> **差 35 个数量级 ⇒ 该值不可能由被描述的路径产生。**

这条判据不需要 oracle、不需要 mpmath、只需要知道浮点尾数位数，因此**可以人工在 review 时执行**。它应当成为 `req-gov-5` 的一类必检项。

## A3 — 三类「看起来像证据的数字」

`req-gov-5` 不写成「所有数字都要有出处」这种无法执行的口号，而写成三类**可机检**的反例：

| 类别 | 形态 | 本仓实例 | 机检手段 |
|---|---|---|---|
| C1 量纲不可能 | 值的小数位数超出其声称的计算路径所能达到的精度 | `5.01e-52` | 位数 vs 尾数位数，无需求值 |
| C2 bracket 冒充根 | 值来自分治/迭代的**收敛判据**，却被标为「根处」「真值处」的量 | 同上（oracle 二分 bracket 残差） | 值必须与「根处」的定义式在同一点求值；否则标注为 bracket 容差 |
| C3 默认值当判据 | 把某 API 的**默认参数值**当作「该 API 的语义」来推理 | `pytest.approx` 的 `rel` 默认（以为是 `1e-6`，实为 `None`） | 读 API 源码 + 行为裁决，不读文档措辞 |

C3 是 Change β 的直接动机。**把三类放在同一条 Requirement 里，是因为它们是同一个失效模式的三张脸**：一个没有 provenance 的数字/断言，在系统里承担了它没有资格承担的证明责任。

## A4 — delta 生成纪律

两份 spec 的 body 是**单行数千字符**（`decompmoe-skeleton` req-6 的 body 曾实测 6 110 字符一整行）。手抄进 delta 必然字符级漂移。

本 change 的 delta 由 `evidence/_gen_alpha_delta.py` 生成，纪律：

- **整行替换**，不用 substring 替换（substring 替换会让原行尾部悬空，产出「结构已坏但 grep 全命中」的文本——本仓踩过，产出文本语义损坏而检查全过）；
- 每条片段必须**恰好命中 1 行**，否则生成器 abort；
- **逐行 `unified_diff` 回验** + 失效 token 扫描（`5.01e-52` / `2.92e-52` 必须归零）。grep 命中是结构损坏时的**假阴性来源**，所以回验必须看 diff；
- block 抽取按 `<a id="req-N"></a>` 锚点切，不按行号（行号会因并行 session 漂移）。

## A5 — 归档副本有意不改

`openspec/changes/archive/2026-10-02-fix-canonical-literal-residual-frame-and-dead-guard/specs/` 下另有 4 处同样的字面量（governance ×3 行、skeleton ×1 行）。

**不改**：归档是「该 change 当时做了什么」的历史记录；改写它等于伪造历史，也会让未来审计无法回答「这个错误数字是怎么进 spec 的」。

**登记**：在 `req-gov-5` 的 Policy lineage 里显式记录「归档副本保留原值，属历史记录」，避免后来者把它当成漏改。

## A6 — 与 Change β 的边界

两处都是 `governance/spec.md` 的真相源错误，但**风险面与优先级不同**，故拆开：

- **α（先）**：`5.01e-52` 被当作 `bisection residual < 1e-9` 这条 MUST 的支点。它污染的是**引证链**——任何引用它做论证的下游 change 都会继承一个假前提。
- **β（后）**：`pytest.approx` 的容差语义陈述错误。判别力结论**不受影响**（两种读法下 `1.275e-6` / `1.297e-6` 都 FAIL、`8.34e-7` 都 PASS），属措辞修复。

但 β 不得拖过下一个迭代：`governance` 义务 1 那条 `abs=0` 的论断会**误导人写出恒真的测试**（以为 `abs=0` 会退化成 `rel·|expected|`，于是用 `approx(x, abs=0)` 写「零容差」断言，而实际上它容差**恰为 0**——测试会通过但形态可疑；反过来若有人为了「真的零容差」而去算 `max(...)`，会写出更弱的守卫）。
