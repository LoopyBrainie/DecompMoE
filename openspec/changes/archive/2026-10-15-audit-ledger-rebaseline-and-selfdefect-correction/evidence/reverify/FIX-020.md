### The enumeration prong — CLOSED, by `df4a1d2`, but not in req-gov-1

The entry's charge was that the threshold rule was "写成逐案枚举白名单而非一般义务".
That formulation is now inaccurate in two ways:

1. **req-gov-1 itself did not change.** Verified by content diff, not by reading:

   ```

        <(sed -n '7,65p' openspec/specs/governance/spec.md)
   ```

   The seven obligations and six Scenarios quoted in this record were already
   present at the pin. Nothing was "added to req-gov-1".

2. **What `df4a1d2` added is a different Requirement.** It created
   `req-gov-13` / `req-gov-14` / `req-gov-15` / `req-gov-16`
   (`governance/spec.md:662`, `:678`, `:694`, `:710`), and
   `req-gov-13`'s `**Source:**` line names the originating change. Those are

   ```
   git log --oneline -S'id="req-gov-13"' -- openspec/specs/governance/spec.md
   → df4a1d2 archive(generalize-numeric-comparison-tolerance-obligation): …
   ```

So the "no general obligation exists" prong is closed, by adding a sibling
Requirement rather than by generalising the one the entry names. The entry's
`location` (`governance/spec.md` req-gov-1, L7–L65) therefore points at the wrong
Requirement for its own second prong.

### The derivation prong — STILL OPEN, and sharpened

The entry's other prong is "无义务把阈值从该 dtype 的 eps 与量的尺度推导出来".
That survives, in a stronger form than the entry states. The general obligation's
closing sentence at `governance/spec.md:666` reads, in the operative part:

> A numerical comparison performed by a comparator whose **relative-tolerance
> parameter defaults to a nonzero value** MUST supply that parameter explicitly,
> and the supplied value MUST be derivable from the magnitude of the protected
> quantity and the precision the spec declares for it. … **A comparator whose
> relative term defaults to absent (an absolute-only form) is not constrained by
> this Requirement.**

Two consequences:

1. The derivation duty is bound to the **rtol parameter**. A bare-scalar absolute
   comparison has no rtol parameter, so nothing requires its threshold to be
   derived at all.
2. The absolute-only class is not merely uncovered — it is **explicitly
   exempted**, by a sentence that names it.

`FIX-029` is exactly that class: `tests/test_metrics.py:166`
`assert eigvals[0].item() < 1e-10`. So the gap this entry identified at the pin
has been converted from an oversight into a stated carve-out, and the carve-out
contains the entire remaining defect family.

This also settles a relationship the entry only gestured at. FIX-020 is the
**upstream** of FIX-029, and `:666` is the mechanism by which FIX-029's threshold
is permitted to exist unchallenged by the governance rule. The entry's
`crossrefs` field lists only FIX-001 / FIX-020's own siblings; the FIX-020 ↔
FIX-029 pairing belongs in the ledger.

## Counting correction

The measuring script originally reported `[1, 2, 3, 4, 6, 7]`. The regex was
`^(\d+)\. \*\*`, which requires the number to be followed by a bold marker;
obligation 5 is written `5. Every assertion …` with no bold and was dropped.
Fixed to `^(\d+)\.\s+\S`, and the true set is the seven above.

```
sed -n '7,65p' openspec/specs/governance/spec.md | grep -oE '^[0-9]+\.'
→ 1 2 3 4 5 6 7
```

This is the fourth instance of the failure mode recorded in `design.md` D-6: a
matcher narrower than the artifact, with its output read as a fact about the
artifact. Instances 1 and 4 are the same mistake twice — write a regex, then
report its output as a count.

## Severity note

The entry rates FIX-020 MAJOR. Measured, that holds. The residue is a single
sentence in one Requirement, so removing it is a surgical edit — but it is a
normative hole in the capability that governs numerical-claim discipline, and it
is currently the only thing authorising the threshold that FIX-029 reports.
