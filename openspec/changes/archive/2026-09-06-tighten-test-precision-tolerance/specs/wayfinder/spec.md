## ADDED Requirements

### Requirement: Test Guard Precision for Closed-Form Numerical Claims

The system MUST guard every spec-anchored closed-form numerical claim with `pytest.approx(value, abs=...)` such that the guard strength matches the actual precision of the closed-form computation. Concrete obligations:

1. **Closed-form integer claims** — claims whose values are exact integers (e.g. `P_total = 452_329_984`, `P_active = 100_008_448`, `P_router/layer = 32_896` from `tests/test_config.py::test_total_param_estimate`; per-layer MoE FLOPs `33_554_432` and total MoE FLOPs `134_217_728` from `tests/test_config.py::test_flops_per_layer_exact_33554432`) MUST use `pytest.approx(value, abs=0)` — NOT raw `==` integer equality — so that the assertion contract is explicit ("spec says this exact value") and the closed-form claim is discoverable via `grep -rn "pytest.approx" tests/`. Note (verified empirically): `pytest.approx(int_value, abs=0)` is **mathematically equivalent to `==`** for `int == int` and `float == int` comparisons — verified that `452329984.0 == pytest.approx(452329984, abs=0)` returns `True`, identical to `452329984.0 == 452329984`. The benefit is convention adherence per `CLAUDE.md` §6 第 8 条 and a natural relaxation point (`abs=0` → `abs=1e-9`) if a future refactor introduces small FP rounding. The actual guard against refactor-induced silent changes is provided by `tests/test_loss.py`-style `pytest.approx(value, abs=tolerance)` matches against computed tolerances.
2. **Bisection-derived Voronoi angles** — claims whose test values come from `canonical_voronoi_angle(N_e, d_c)` (which solves `½ · I_{sin²θ}((d_c − 1)/2, 1/2) = 1/N_e` via bisection) MUST use `pytest.approx(value, abs=1e-6)` — NOT `abs=1e-4` or wider — because the bisection implementation achieves residual `|½ · I_{sin²θ}(7.5, 0.5) − 1/N_e| < 1e-9` (proven by `tests/test_sphere.py::test_voronoi_residual_below_1e_minus_9`); a 1e-6 tolerance is therefore strictly above the bisection noise floor. The **test literals** for these assertions are the actual bisection output rounded to 6dp (e.g. `1.173548 rad` for `(16, 16)` matches bisection `1.1735482746999482` to within `3e-7`); these test literals are distinct from the **canonical spec literal** `67.24° (1.1736 rad)` declared in Requirement 11 (the degree-to-radian conversion-consistency form, where `67.24° × π/180 = 1.1735593890 rad` rounds to `1.1736` at 4dp). The `1e-4` gap between `1.173548 rad` (bisection 4dp) and `1.1736 rad` (degree-conversion 4dp) is an acknowledged 4dp rounding artifact, separately guarded by `tests/test_sphere.py::test_voronoi_rad_precision_alignment` at `abs=1e-4`. This obligation does not change the canonical spec literal declared in Requirement 11 — only the test guards that pin bisection-precision values.
3. Every assertion described in obligations 1 and 2 MUST embed `f"actual={...}"` in its failure message so a numerical regression surfaces the actual computed value at the assertion site (per `CLAUDE.md` §3 TDD convention), EXCEPT assertions using `pytest.approx(value, abs=...)` whose pytest assertion rewriting already produces a side-by-side `actual vs expected` diff in the failure output — in those cases the existing `f"got {actual}"` form (or no message) satisfies this obligation because the pytest diff already displays both values. This exception is documented in `design.md` Decision 3 and applies to the 3 LOW-3/LOW-4 bisection assertions at `tests/test_sphere.py` L90, L91, and L141 (which use `f"got {actual}"`); the 5 LOW-1/LOW-2 integer assertions MUST use `f"actual={...}"` because `pytest.approx(int_value, abs=0)` on `int == int` does not produce an informative pytest auto-diff (the diff shows only `int_value != int_value`).

This requirement is a test-side convention that complements — but does not replace — the closed-form numerical claims codified in Requirement 11 (`4070 MVP Hyperparameter Set`). The closed-form values themselves are unchanged; only the test guards that pin them tighten. This requirement applies prospectively to any new test that pins a closed-form numerical claim from `wayfinder` Req 11; existing tests that already meet the precision bar are not required to be tightened further by this requirement.

**Source:** `tests/test_config.py` (LOW-1 `test_total_param_estimate`, LOW-2 `test_flops_per_layer_exact_33554432`), `tests/test_sphere.py` (LOW-3 `test_voronoi_monotone_in_ne`, LOW-4 `test_voronoi_canonical_N_e_dependence`), `tests/test_sphere.py::test_voronoi_residual_below_1e_minus_9` (bisection precision witness), `tests/test_sphere.py::test_voronoi_rad_precision_alignment` (spec conversion-identity witness at `abs=1e-4`, complements the bisection-precision test at `abs=1e-6`), `CLAUDE.md` §3 (TDD `f"actual={...}"` convention), `CLAUDE.md` §6 第 8 条 (closed-form `pytest.approx` mandate).

#### Scenario: Closed-form parameter totals use abs=0

- **WHEN** a test verifies any of `P_total == 452_329_984`, `P_active == 100_008_448`, `P_router/layer == 32_896` (closed-form integer parameter claims from Requirement 11 "Closed-form parameter totals")
- **THEN** the assertion uses `pytest.approx(value, abs=0)`, embeds `f"actual={...}"` in its failure message, and a raw `==` integer comparison MUST NOT appear.

#### Scenario: Closed-form FLOPs totals use abs=0

- **WHEN** a test verifies per-layer MoE FLOPs `33_554_432` or total MoE FLOPs `134_217_728` at one of the LOW-2 audited sites specifically (i.e. `tests/test_config.py::test_flops_per_layer_exact_33554432` L80 and L81 — see `tasks.md` §1.2)
- **THEN** the assertion uses `pytest.approx(value, abs=0)`, embeds `f"actual={...}"` in its failure message, and a raw `==` integer comparison MUST NOT appear. The unrelated test `tests/test_config.py::test_flops_total_exact_134217728` (L86) verifies the same constant `134_217_728` but is EXPLICITLY OUT OF SCOPE per `design.md` Decision 4 — the audit findings named only `test_flops_per_layer_exact_33554432`, and this change keeps the LOW-2 scope to L80/L81 to avoid expanding beyond the audited envelope (`CLAUDE.md` §3 "Touch only what you must").

#### Scenario: Bisection Voronoi angles use abs=1e-6

- **WHEN** a test verifies a bisection-derived Voronoi half-angle at one of the LOW-3 or LOW-4 audited sites specifically — namely `tests/test_sphere.py::test_voronoi_monotone_in_ne` L88-93 (LOW-3, asserting `θ_Voronoi(16, 16)` and `θ_Voronoi(17, 16)`) and `tests/test_sphere.py::test_voronoi_canonical_N_e_dependence` L138-152 (LOW-4, asserting `θ_Voronoi(64, 16)`) — using the bisection-6dp test literals `1.173548 rad`, `1.165848 rad`, and `1.020507 rad` (each within `3e-7` of actual bisection output)
- **THEN** the assertion uses `pytest.approx(value, abs=1e-6)`. Other tests that verify bisection-derived Voronoi half-angles under the prior convention are EXPLICITLY OUT OF SCOPE for this Scenario until a future change audits them: `tests/test_sphere.py::test_voronoi_rad_precision_alignment` (asserting the conversion identity `67.24° × π/180 ≈ 1.1736 rad` at `abs=1e-4` — pre-existing test, conversion-identity perspective, not bisection-precision), `tests/test_sphere.py::test_versine_voronoi_closed_form` (L204-L215, asserting `versine_Voronoi` at `abs=1e-4` — pre-existing test, NOT in the audit envelope), and any other pre-existing tests that verify bisection-derived values with `abs=1e-4` or wider tolerance.
