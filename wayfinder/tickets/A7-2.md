## Question

Decode 阶段 C 如何从 `C_t` 递推到 `C_{t+1}`？

候选（取决于 A3-1 算子）：
- **(O) Online PCA**：用 rank-1 update 维护 leading singular vector（Oja's rule）
- **(E) EMA**：`C_{t+1} = α · C_t + (1-α) · f(k_{t+1}, v_{t+1})`
- **(P) Power iteration in place**：复用 C_t 作为 init，跑 1-2 步幂迭代
- **(R) 直接重算**：如果 A3-1 = L（可学习投影），根本不用增量

**关键问题**：
- 增量误差累积怎么办（每 N 步做一次 full recompute reset）？
- C 状态在 KV cache 中的存储开销（per layer × per head × d_c）？

## Resolution

**锁定：(R) 无状态逐帧重算**

### 数学形式

```
C_t = L2_Norm( (1/H_kv) · Σ_h L2_Norm(W_h^K k_t^{(h)} + W_h^V v_t^{(h)} + b_h) )
```

### 性能指标

| 指标 | 数值 | 说明 |
|---|---|---|
| **FLOPs/token** | ~65.5K | 4 · H_kv · d_k · d_c (H_kv=8, d_k=128, d_c=16) |
| **HBM 读写** | 0 Bytes | C_t 走 SRAM/Registers，零 HBM 流量 |
| **存储生命周期** | 随用随弃 | 不写入 KV Cache，不跨 step 复用 |

### FLOPs 对比（Decode 单 token，d=2048）

| 算子 | FLOPs/token | 占总 decoder 时间比 |
|---|---|---|
| Attention (Q · K^T) | ~4.2M | 主导 |
| FFN (k=2 experts) | ~16.8M | 主导 |
| C 提取 (本设计) | 65.5K | ~0.3% |
| Logit + Softmax + Top-k | ~10K | <0.1% |
| **合计** | ~21M | — |

C 提取对总 decoder latency 的影响 < 0.5%。

### 三类演化解耦（spec 全文遵循）

| 对象 | 增量性 | 更新机制 | 频率 |
|---|---|---|---|
| `C_t` (per-token) | ❌ | 逐帧重算 | 每个 Decode step |
| `c_i` (territory centers) | ✅ | A3-2: Masked Spherical EMA (P1-3) / Projected SGD (P4) | 每个 training step |
| `W_proj` (W^K, W^V, b) | ✅ | AdamW | 每个 training step |

### 与 A3-1 / A7-1 协同

- **A3-1 (L') 投影**：决定了 C 提取的复杂度形式（O(d_c · d_k) per token）
- **A7-1 禁 C 缓存**：决定了"无状态"语义（无 carry-over 状态）
- **A7-2 重算**：明确了 C 在 inference 时是 stateless function of (K_t, V_t)

### 后续 ticket 影响

- A7-3 (硬件友好度)：0 HBM 读写 + 65.5K FLOPs 是硬件设计的关键数字
- A8-1 (Baseline)：所有 baseline 同样 stateless C 处理

### Future Work

- **C 跨 step 缓存（speculative）**：如果 latency 要求极致，可考虑缓存最近 N 步 C 复用
- **Online PCA / Power Iteration**：spec 末尾标注，留作精度 / 速度 trade-off ablation
- **C 跨层共享**：相邻层 C 可能冗余，spec 复杂，Future Work
