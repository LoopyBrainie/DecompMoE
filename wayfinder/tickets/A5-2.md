## Question

DeepSeek-MoE 风格有"共享专家"概念——始终激活、承担通用知识。本设计怎么处理？

候选：
- **(0) 无共享专家**：所有专家都路由，k 个被选
- **(S) 显式共享专家**：1-2 个专家 σ → ∞，永远激活，输出与其他专家相加
- **(∞) 数学极限建模**：共享专家 = σ → ∞ 的几何极限情况
- **(G) 全局背景领地**：把共享专家视为"σ 极大、c_i 任意"的几何原型

**关键问题**：
- 如果走 (S) 或 (G)，共享专家的参数是独立学还是用 frozen pretrained FFN？
- 共享专家与路由专家的输出聚合方式（add / weighted add / concat）？

## Resolution

**锁定：(0) 无共享专家（Pure Geometric Routing）**

### 前向算子（与 A4-2 一致）

```
x_out = x + Σ_{i ∈ I_k} p_i · Expert_i(x),    Σ_{i ∈ I_k} p_i ≡ 1.0
```

### 数学保证

1. **方差无漂移**（深层网络稳定）
   - 增量条件方差：`Var[Δx | x] ≤ σ_e²`
   - 杜绝深层协方差干扰
   - 前提：交叉协方差项 `Cov[Expert_i, Expert_j | x] ≈ 0`（在专家独立初始化 + 训练充分分化下严格成立）

2. **槽位无侵占**
   - k 个激活名额 100% 留给几何领地划分出的特化专家
   - 无"always-on"路径占用 routing capacity
   - Routing 信号纯净

3. **架构完全对齐**
   - 与 Mixtral-8x7B 的 Clean Form 结构同构
   - baseline 对比无歧义

### Caveat（用户补充的严谨性声明）

> *在专家参数独立初始化 AND 训练充分分化的条件下，交叉协方差项 `Cov[Expert_i, Expert_j | x] ≈ 0`，方差上界严格成立。*

- 独立初始化：Kaiming/Xavier per-expert
- 训练充分分化：A3-2 4 阶段生命周期 + A6b 退火调度
- 若任一前提不满足，covariance 项不严格为零，方差上界变松

### 后续 ticket 影响

- A5-3 (超参 Scaling)：直接用 Mixtral 风格 scaling 范式（无 shared expert 干扰）
- A6a-1 (损失函数)：L_lb 作用在所有 N_e 个专家上，无"shared + routed"双层结构
- A6b-1 (4 阶段)：无需为 shared expert 单独设计阶段，所有专家同步生命周期

### Future Work

- **(S) Explicit Shared Expert**：MVP 后可加入 1-2 个 always-on expert，公式扩展为：
  `x_out = x + SharedExpert(x) + Σ p_i · Expert_i(x)`
- **(∞) 球面 β → 0 极限**：将 shared expert 几何化为"覆盖整个球面"的低 β 专家，与 routing 专家区分
