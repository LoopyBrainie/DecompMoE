## Question

每个专家内部的网络结构选什么？

候选：
- **(S) 标准 SwiGLU FFN**：与 Llama baseline 同构（`down(SiLU(gate(x)) * up(x))`），结构最简单
- **(L) 轻量级低秩网络**：专家参数极少（如 2 个小矩阵乘）
- **(G) 几何线性层**：输入经过 (C - c_i) 调制后再 FFN（专家有结构感知）
- **(M) Mixture-of-Experts inside expert**：每专家再嵌一个子 MoE（嵌套结构）

**关键问题**：
- 专家是替换原 FFN 还是叠加在原 FFN 上？
- 专家是否要共享参数（不同专家用同一组 FFN 权重，但不同 bias）？
- Activation 形状（hidden dim × expansion ratio）？

## Resolution

**锁定：Standard SwiGLU FFN，与 Llama baseline 结构同构**

### 数学形式

```
Expert_i(x) = (SiLU(x · W_i^g) ⊙ (x · W_i^u)) · W_i^d
```

### 参数维度

- `W_i^g ∈ R^{d_model × d_ffn}`（Gate Projection）
- `W_i^u ∈ R^{d_model × d_ffn}`（Up Projection）
- `W_i^d ∈ R^{d_ffn × d_model}`（Down Projection）
- 无 bias（与 Llama 主流实现一致；bias 是 spec 内部可选开关）

### 单专家参数量

```
|Expert_i| = 2 · d_model · d_ffn + d_ffn · d_model = 3 · d_model · d_ffn
```

### 与 dense baseline 的关系

| 模式 | 参数量 | 激活/token |
|---|---|---|
| Dense FFN | `3 · d_model · d_ffn` | 同左 |
| DecompMoE 总 | `N_e · 3 · d_model · d_ffn` | `k · 3 · d_model · d_ffn` |
| DecompMoE / Dense 总参数比 | `N_e : 1` | — |
| DecompMoE / Dense 激活参数比 | — | `k : 1` |

- 假设每个 expert 的 d_ffn 跟 dense baseline 一样（标准 MoE 范式：Mixtral 8x7B、DeepSeek-V3 都这样）

### 控制变量保证

- Expert 内部**无任何路由信号 C 的注入**
- Expert 内部**无 c_i, β_i 调制**
- 性能差异唯一归因于 A0-A4 几何路由链条（A0 命名 + A1 符号 + A2 拓扑 + A3 C 提取 + A4 门控）
- 这条是 MVP 验证性的核心约束

### 工程保证

- 直接复用 vLLM / Megatron-LM / DeepSpeed-MoE 的 SwiGLU fused kernel
- 零 custom op，零 kernel 重写
- 与 A2-1 Post-FFN 替换对齐：每个 FFN 槽位变成一个 `GeometricRouter + N_e Experts` 的组合

### 后续 ticket 影响

- A5-2 (共享专家)：共享专家如何融入这个 SwiGLU 结构
- A5-3 (超参 scaling)：d_ffn 怎么选（沿用 dense baseline 4/3 还是 MoE 标准 8/3 split）
- A6a-1 (损失函数)：Expert 内部无 C 注入，损失项不需额外考虑 expert 内部结构

### Future Work

- **(G) Geometry-Aware Expert Conditioning**：专家内部引入 C 调制（FiLM / Cross-Attention 风格）——"double geometric"，复杂度高
- **(L) Low-Rank Expert**：极端稀疏场景下的秩分解优化
